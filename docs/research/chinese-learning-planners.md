# 中文儿童与家庭学习计划产品调研

调研日期：2026-11-11。关联 [调研儿童家庭学习计划产品，为首版方向提供依据](https://github.com/Limilylee/tasklist/issues/1)、[调研中文小学生与家庭学习计划产品](https://github.com/Limilylee/tasklist/issues/2)。

## 结论与证据边界

建议先验证 **星目标的亲子执行流程**与 **滴答清单的时间安排流程**；番茄ToDo适合研究专注计时，小日常适合研究简洁的每日打卡。这个排序是针对一般家庭学习管理的推断，不代表完成安装后的体验排名。

通用假设：家长需要录入临时作业与额外练习，并与固定课程协调；产品应支持日、周和假期计划。以下时间、时长与任务示例仅为通用测试假设，不描述任何实际家庭。

本报告仅核对官网、官方帮助中心、开发者提交到正式应用商店的文案及版本历史，未安装、注册、购买或实际操作候选产品。商店中的用户评论不作为功能证据。以下“未知”表示本轮一手资料未确认，不能理解成产品没有该能力；iOS更新说明也不等于Android同版本已上线。

本轮未验证任何特定设备的安装、系统最低要求、后台提醒或同步。需取得实际分发包核对，并在目标设备测试。

## 逐款核查

### 星目标：儿童角色与假期切换值得借鉴

开发者定位4–12岁；家庭成员共享、儿童模式、学习机云共享、正/倒计时均有明确文案。iOS版本历史记载：上学日/法定节假日与自定义寒暑假周期、AI作业识别、日历时间轴；还有家长端/儿童端设置和审核机制。[S1][S2] **AI识别不等于外部消息自动抓取**，其输入格式、识别准确率、Android功能一致性均未知。

推断：可用常规计划放英语、口算，用假期计划切换强度；老师作业作为当天临时内容。核心测试是孩子能否只调当天顺序而不能误改周期，以及任务超时后能否看到学习结束边界并选择删减。未找到一手资料证明自动顺延后续任务或自动检查总时长。

分发：有中国区iPhone/iPad商店页，以及标注手机/平板的Android小米商店页；后者同日浏览器核查看到1.10.6、更新日2026-10-31，但下载按钮标“维护中”，不能据此保证能下载或侧载。Mac完整编辑入口未确认。商店标免费并含内购；iOS列年卡¥99、永久会员¥159，**仅为该渠道当次公开展示**，不代表Android同价或相同权益；应先查清家庭成员、审核、作业识别和日历的实际限制。[S1][S2]

### 滴答清单：时间轴、批量录入与共享清单证据最具体

官方说明支持日/周视图、无时间任务待安排区、拖动任务及边缘调整时长。[D2] 可先把乒乓球、写字课放成重复安排，再将临时作业放入剩余学习时段；这是使用建议。共享对象是自己创建的清单，智能清单及收集箱不能直接共享。[D3] 因此应创建专门的“孩子学习”清单，而不是假定家长的“今天”视图会原样出现在孩子端。

外部消息录入有可证实的低成本手动路线：家长复制文字、整理成每行一项，粘贴网页输入框可批量创建；剪贴板添加也是独立官方能力。[D4][D5] 外部消息自动读取、图片作业自动拆分和消息补发合并未确认。建议先整理待安排项，补录时显式检查重复与遗漏。

超时：官方更新记录支持补充额外专注时长及手动调整记录，并记载批量推迟任务的功能。[D6] 这些分别是记录与手动调整，不能推断为“当前任务延误就自动重排整晚”。孩子可否只调整自己的顺序、共享成员是否能看到专注时长，也需实测。

分发：官网列Android、macOS、iOS/iPadOS与网页版等入口。[D7] 免费方案有提醒及多端同步；公开高级方案为¥139/年，包含任务时间段和更多日历视图。[D8] 是否家长、孩子两账号均需高级会员，取决于各自要用的功能，本轮没有直接结论；购买前分别在两账号确认。

### 番茄ToDo：专注执行强，家庭时间安排待证

Android开发者文案明确待办、重复、到点提醒、云同步与专注统计；iOS文案另列正向的专注与自习室体验。[F1][F2] 学霸模式与同伴自习室不能证明有家长配置、孩子执行、家长审核的角色流程。每日清单/重复任务也不自动等于周课表或寒暑假模板。

推断：可以研究20分钟口算、15分钟英语等单项执行，但不应默认25分钟适合所有儿童；应由使用者选择长度。剩余学习时间、当前超时、取消/补记、顺序调整和提醒升级需逐一观察，未确认自动重排。

分发：Android小米商店存在正式条目，网页同样标维护中；iPhone/iPad商店标免费含内购，未在本报告给出未经统一核对的会员价格。[F1][F2] 官方提供M芯片及Intel Mac桌面计时插件，但说明需连接手机；**这不能当作已确认可独立编辑全部计划的Mac客户端**。[F3] 跨账号亲子同步、多个设备同时登录的冲突规则未知。

### 小日常：适合轻量习惯，不宜据名称推断儿童计划能力

本报告锁定广州小日常科技有限公司的Android产品，包名 `com.dandelion.routine`，避免把同名苹果应用的iCloud等文案拼接到它身上。开发者条目确认习惯分组、量化、临时待办、正/倒计时、补记及统计；未找到足以确认周时间轴、固定课程冲突或家庭账号的资料。[X1]

推断：阅读、朗读和每日口算适合习惯卡片；每天内容不同的消息作业需要额外临时录入与时长安排。可以借鉴图标、颜色与一键完成，但还需要独立的“今天剩多少时间”机制。

分发：小米商店仍有2026-11-05更新的条目，网页标维护中，不能保证浏览器直接下载成功。该准确产品的Mac入口、跨平台同步方式、最新付费价格与免费限制均未从本轮一手资料确认。[X1] 名称相同不证明iOS/Android是同一数据服务。

## 给原型的具体启发（设计推断）

1. 将“周期计划”和“今天的作业”分开：日常/周末/假期是模板，临时更新的作业进入当天待安排区；保留原始消息文字或图片供人工核对。
2. 显示可用学习窗口的真实容量：固定课、休息与缓冲也占时间。待办全部打卡不是唯一成功标准，孩子应能看到下一件和预计结束时间。
3. 亲子权限要可解释：家长决定任务与不可移动的课程；孩子调整允许移动的任务顺序、开始、暂停、完成或请求帮助。审核与奖励可以存在，但应避免每一步都依赖家长批准。
4. 建议为超时提供可选动作：继续5分钟、稍后做、请家长协助、减掉可选任务；重新展示结束时间，帮助家庭决定是否调整预定结束边界。
5. 同步需区分角色：同账号备份、多设备同账号同步、多人共享清单、受限儿童账号是四种能力；选型和原型均应分别验证。

## 首轮实测问题与通过条件

| 测试 | 具体问题/通过条件 |
| --- | --- |
| Android10与安装 | 从开发者或正式渠道获取实际包；记录版本、最低系统、包名及来源。目标设备是否允许安装、更新、通知、后台与所需权限？不得用“Android”宣传代替通过记录。 |
| 家长到孩子 | Mac/手机创建一条任务，孩子端多久出现？孩子完成后家长多久看到？离线改动重连是否冲突、丢失或重复？ |
| 孩子自主性 | 让儿童自己找到下一项、开始、暂停、完成、换顺序；是否误改了固定课程或后续所有重复任务？ |
| 外部消息手动录入 | 先录入包含文字、图片、两科作业的消息；随后补发或更正。是否能保留出处、去重、人工拆分且不漏项？记录实际耗时。 |
| 容量（通用假设） | 安排共145分钟的任务，是否清晰暴露超量？一项超时15分钟后，后续课和预定截止是否仍可见？任何自动变化是否允许撤回？ |
| 锁屏与后台 | 插电/不插电、锁屏30分钟、切到教材、断网恢复、重启分别测试指定时间提醒与计时结束；记录声音、亮屏、通知、迟到秒数和是否需家长处理。 |
| 周与假期 | 固定乒乓球/写字课重复；单次调课不能影响整学期。切到暑假后，日常计划能否暂停、恢复，是否重复生成任务？ |
| 价格与限制 | 免费账号先走完家庭最小流程；分别列出两账号的时间轴、共享人数、提醒、审核、识别、历史统计限制，再决定是否付费。 |
